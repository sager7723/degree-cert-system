# 第 4 步：准备应用身份并构建核心合约

第三步已确认四节点与 Go VM 运行，CMC 读到 chain1 的区块高度 8。本步让普通用户通过三个机构身份访问链，并在 Ubuntu 编译、打包第一版核心学历证书存证合约。合约部署是下一步，本步不会修改链上证书状态。

## 1. 将虚拟机内存调整为 8 GB

原报告只有约 304 MiB 可用内存，交换空间已使用 2.5 GiB。用户已选择将虚拟机内存调整到 8 GB：在 Ubuntu 正常关机，待 VMware 显示关闭电源后，进入“编辑虚拟机设置 → 内存”，设置为 8192 MB，再启动 Ubuntu。不要使用挂起或直接强制断电。

开机后在 Ubuntu 终端执行：

```bash
free -h
cd /home/wsc/degree-cert-system
sudo -v
bash scripts/03-start-and-query.sh
```

总内存通常显示约 7.7 GiB。已有四节点都在线时，第三步脚本会跳过启动；全部离线时，按原拓扑恢复。确认再次出现“链读取验证通过”后再继续。若报告显示部分节点已运行导致停止，先反馈该报告，不重复强制启动。

## 2. 将第四步代码包放入 Ubuntu

Windows 资料文件夹中有 `degree-cert-system-step04.zip`。将它拖入 Ubuntu 的“下载”目录，路径为 `/home/wsc/Downloads/degree-cert-system-step04.zip`。

在 Ubuntu 中执行：

unzip -o /home/wsc/Downloads/degree-cert-system-step04.zip -d /home/wsc/degree-cert-system

## 3. 执行准备与构建

只复制下面代码框内的命令，不要复制反引号标记或终端提示符：

```bash
cd /home/wsc/degree-cert-system
sudo -v
bash scripts/04-prepare-development.sh
```

脚本会依次完成：

1. 复制三个组织已有的 client1 身份到 `instance/chain-identities/`；目录权限为 700，文件为 600，只复制各组织公开 `ca.crt`，不复制 CA 私钥或管理员私钥，不改变原文件权限。
2. 对每套 TLS 和签名证书进行证书/私钥公钥匹配检查及 CA 验证。只输出证书元信息，不输出私钥正文。
3. 生成 `config/sdk-uni.yml`、`sdk-edu.yml`、`sdk-query.yml`。高校映射 org1，监管映射 org2，查询映射 org3；都连接 org1 的 12301，因此都使用 org1 的 CA 信任 RPC 服务端。
4. 从普通用户可写目录执行三次真实区块查询。身份材料是现有客户端的受限副本，不是新签发证书；后续网页进程无需 sudo。
5. 读取实际链配置中的 VM 支持列表。v2.4 中 `GO` 与 `DOCKER_GO` 为不同枚举，先确认支持情况再选部署参数。
6. 使用现有 Go 1.18 运行核心测试，再离线编译为 Linux amd64 静态程序，用 7z 打包。依赖已包含，无需下载 Go 模块，也无需全局安装 Python 包。

首次编译需要几分钟。若某一步失败，脚本停止后续动作，并保留已有成果；不要删除身份文件或重建链，把错误发回即可。
