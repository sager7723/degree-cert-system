# 查询功能升级：编号、姓名、学校、学号与签发时间排序

适用：第六步已经安装并通过网页业务验收的现有系统。Windows 更新包不会自动同步到 Ubuntu，需要按下文复制和解压。

## 更新后的查询规则

| 查询类型 | 输入 | 返回内容 |
| --- | --- | --- |
| 证书编号 | 完整编号，保持大小写一致 | 精确定位该编号的单张证书 |
| 学生姓名 | 完整姓名 | 所有同名学生的全部证书，包括不同学号和不同学校的学生 |
| 学校名称 | 完整学校名称 | 该校在本系统登记的全部匹配证书 |
| 学号 | 完整学号 | 该学号对应的全部证书 |

查询内容会去除首尾空白并进行 Unicode NFC 规范化。姓名和学校采用完整匹配，例如“演示大学”不会匹配“演示大学分校”。高校、监管账号还保留“综合关键词”部分匹配和全库浏览。

查询机构工作台现在直接提供查询表单。结果包含有效、已撤销等本地已登记记录，每页 20 条，提供总数和翻页，不会仅返回前 200 条。默认按签发时间从早到晚排列，可切换为从晚到早。切换查询条件或排序后点击“查询”生效。

签发时间取自已经确认的链记录 issued_at，而不是毕业日期、本地录入时间或撤销时间。同一秒签发的记录按证书编号排序，未取得已确认签发时间的记录排在最后；页面显示 UTC+8 时间。

查询范围是本系统 SQLite 已登记的证书。链上保存摘要和状态，姓名、学校全文保存在本地；进入详情、核验内容时继续读取真实链。查询机构仍然没有签发、撤销权限。

## 原完整编号查不到的原因

原查询表单提交的字段名为 search，后端读取的字段名为 q，导致输入值未被实际使用。现已统一为 q，并兼容旧 search 链接。新增回归检查从真实 HTML 表单提取字段名再提交查询，覆盖这类前后端参数不一致问题。

## 同步到 Ubuntu

1. 将 Windows 中的 degree-cert-system-step06-fix3.zip 复制或拖放到 Ubuntu 的 /home/wsc/Downloads。不要解压到 Windows 后只复制其中某个模板，本次需要一起更新后端、模板和样式。
2. 在运行网页的 Ubuntu 终端按 Ctrl+C，停止网页服务。链节点保持运行。
3. 在 Ubuntu 终端依次执行：

```bash
cd /home/wsc/degree-cert-system
unzip -o /home/wsc/Downloads/degree-cert-system-step06-fix3.zip -d /home/wsc/degree-cert-system
bash scripts/07-start-web.sh
```

4. 保持服务终端运行。在 Ubuntu 浏览器打开 http://127.0.0.1:8080，并按 Ctrl+Shift+R 强制刷新。登录 query_user。

此包只包含更新的代码、测试和说明，不包含 instance、config、数据库、账号密码或链身份。无需 sudo、重新安装依赖或重新部署合约，也不需要运行第五步。本次更新保留左侧栏滚动和左栏底部退出入口。

## 浏览器验收

1. 工作台出现“查找学历证书”及查询类型、查询内容、签发时间排序三个控件。
2. 选择“证书编号”，输入 DEMO_20260927083846_c03f4591_B，应只返回 B；进入详情，应仍有效。
3. 选择“学生姓名”，输入“演示同学”，应查出已有 A、B，以及之后签发的所有同名证书（如有）；不能因为学号不同而遗漏。
4. 选择“学校名称”，输入“演示大学”，应返回本系统该校的所有证书，包括已撤销 A 与有效 B，以及此前网页签发的该校证书（如有）。其他学校不应混入。
5. 分别选择“从早到晚”和“从晚到早”并查询，检查“签发时间”列。相同秒数仍按证书编号排列。超过 20 条时使用“下一页”，查询类型、查询内容、排序应保持不变。
6. 输入一个不存在的完整编号，应明确提示“没有找到匹配的证书”，不能退回全库列表。

可以使用现有数据完成验收，无需为了测试重新签发或撤销证书。姓名、学校以已有证书实际内容为准。
