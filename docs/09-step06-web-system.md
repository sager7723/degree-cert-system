# 第六步：安装网页与浏览器业务验收

前提：第五步报告已显示“第五步全部通过”，现有 chain1 节点与 Docker VM 仍在运行。本步使用已部署的 degree_cert_v1 合约。

已安装第六步的用户，按 [查询功能升级说明](15-step06-search-upgrade.md) 安装 fix3 增量包。下述查询能力以该更新为准，不需要重新安装依赖。

## 1. 放置增量包并安装

把 Windows 的 `degree-cert-system-step06.zip` 拖入 Ubuntu 的 `/home/wsc/Downloads`。在 Ubuntu 终端执行（不用 sudo）：

```bash
cd /home/wsc/degree-cert-system
unzip -o /home/wsc/Downloads/degree-cert-system-step06.zip -d /home/wsc/degree-cert-system
bash scripts/06-install-web.sh
```

ZIP 直接解压到已有项目内，不要再套一层同名目录。包中只有代码、离线依赖及说明，没有 instance、config、数据库或身份文件。

安装脚本在已有 `.venv` 内校验 SHA-256 并安装离线依赖，读取真实合约，创建 SQLite 与三角色账号，核对第五步两张演示证书的全文哈希后导入。它不重新部署合约或发送签发、撤销交易。

首次安装应显示导入数量 2、网页与真实合约 health 检查通过，最后“第六步完成”。重复运行不重置密码或重复导入，导入数量为 0 属于正常情况。依赖包适用于当前 Ubuntu x86_64、CPython 3.12。

如果虚拟机已经重启、链未运行，先按第三步恢复已有链再安装。缺少 `.venv` 或第五步文件时保留失败报告供排查，不要删除原状态或重新部署合约。

## 2. 查看账号并启动

在项目目录执行：

```bash
cat instance/demo-accounts.json
bash scripts/07-start-web.sh
```

密码随机生成，以账号文件为准，只在本机查看，不需要反馈其内容。

| 账号 | 角色 | 权限 |
| --- | --- | --- |
| uni_admin | 高校签发机构 | 签发、查询、核验、导出、查证自己的交易、查看日志 |
| edu_admin | 教育主管部门 | 查询、核验、导出、撤销、查证自己的交易、查看日志 |
| query_user | 查询机构 | 按完整证书编号、姓名、学校或学号查询，按签发时间排序、翻页、核验、导出 |

保持终端运行，在 **Ubuntu 内的浏览器** 打开 `http://127.0.0.1:8080`。Windows 浏览器中的 127.0.0.1 指向 Windows，不能直接访问这个 Ubuntu 地址。可以直接录制 Ubuntu 浏览器。

## 3. 查看已有证书

用 uni_admin 登录。工作台显示真实合约连接状态；进入“证书查询”应看到：

- `DEMO_20260927083846_c03f4591_A`：已撤销。
- `DEMO_20260927083846_c03f4591_B`：有效。

两张证书属于同一学生。列表和统计标明本地记录状态；进入详情会重新读链、计算全文哈希，分别显示内容匹配与链上状态。

从 A 详情点击“核验内容”，直接核验应显示“内容一致，但证书已撤销”。B 应显示“内容一致，证书有效”。链不可达时显示无法核验，不把本地缓存作为本次成功结果。

## 4. 网页真实业务验收

这部分会发送真实演示交易。使用虚构信息，保留 A、B 作为已有对照，另建一张 C：

1. uni_admin 进入“签发证书”，保留自动生成的编号。填写学号 `DEMO-WEB-001`、姓名“网页演示同学”、院校“演示大学”、专业“计算机科学与技术”、层次“学士”、毕业日期 `2026-06-30`，签发后应显示已确认、有效和签发交易 ID。
2. 记录编号，从详情点击“核验内容”，直接核验应内容一致且有效。
3. 仅把核验表单的专业改为“软件工程”，再次核验应摘要不一致。核验不修改原证书或链上数据。
4. 回到原详情，“导出证书”保存 JSON。在“内容核验”展开“导入证书文件”，选中 JSON 后核验，应内容一致且有效。选了文件便以文件内容为准。
5. 退出，用 query_user 登录，选择“证书编号”，按完整新编号查询、核验；再选择“学生姓名”查“网页演示同学”，选择“学校名称”查“演示大学”，检查全部匹配记录与签发时间排序。该角色没有签发与撤销权限，后端和合约也分别检查权限。
6. 退出，用 edu_admin 登录，在 C 详情填写撤销原因“网页验收：演示监管撤销”并撤销，应显示已撤销、交易 ID 与原因。
7. 再核验原内容或原 JSON，应显示“内容一致，但证书已撤销”；原哈希不变。再查 B 应仍有效。
8. 对应发起账号的“交易记录”显示自己的签发或撤销；“操作日志”记录登录、核验和业务操作。

若显示待链上确认，在“交易记录”点击“查证原交易”。它只读已保存的交易 ID，不重发。仍待确认时保留记录并反馈，不要删数据库或换编号盲目重试原操作。

## 5. 重新启动与反馈

在服务终端按 Ctrl+C 只停止网页，链节点继续运行。随后执行：

```bash
cd /home/wsc/degree-cert-system
bash scripts/07-start-web.sh
```

重新登录检查数据、交易和撤销状态仍在，密码不变。这验证网页进程重启后的持久化；整个 Ubuntu 重启后的链恢复仍按第三步执行。

安装报告在 `reports/stage06-日期时间-随机后缀/report.txt`，脚本结尾会显示精确路径。请反馈 report.txt，以及是否能登录、A/B 状态、网页新签发与撤销结果。异常时反馈页面提示、证书编号、交易 ID 和终端报错即可；账号密码、私钥、会话密钥不需要反馈。

数据库为 `instance/degree-cert.sqlite3`；SQLite 的 -wal、-shm 也是运行数据。不要在运行时手工编辑或只复制单个数据库文件作备份。原始链输出在 `instance/chain-calls`，仅供本机排查。

交付前已做本地自动化测试和浏览器检查，使用独立测试数据。网页到 Ubuntu 真实链的最终成功，以本步骤报告及浏览器业务结果为准。
